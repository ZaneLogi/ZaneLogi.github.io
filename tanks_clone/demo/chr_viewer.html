tanks_clone — CHR viewer · Battle City (J), NROM, fixed 8 KB CHR

Sprites — tiles $00–$FF · CHR $0000–$0FFF

 

Every sprite is 8×16 ($2000 bit 5) — the 8×8 view is raw tile order and reads as garbage. A 16×16 tank is 2 of these side by side. Palette is per-slot: $DFE8 does TXA, so the tank's slot index IS its palette (0 = P1, 1 = P2). Enemies look up tbl_E003; a bonus tank (tank_type & $04) flashes 2↔3 every 8 frames.

Background — tiles $00–$FF · CHR $1000–$1FFF

 

These glyphs have no palette of their own. The only per-item attribute write in the game is sub_D612, called from exactly one site — $D81E, the terrain-block writer. Text just inherits the palette of the 32×32 attribute quad it lands in. The default is palette 0 ($D7E1 clears the whole attribute shadow at $07C0 to $00); screens then override regions by hand, e.g. sub_D0D9 for the score screen. So pick a palette below — the ROM has no single right answer.

Table split is decoded, not assumed: the NMI writes $2000 = ram_base_nmt | $B0 (vec_D400_NMI, $D41F) — bit 4 = 1 puts the background at $1000, bit 3 = 0 puts sprites at $0000, and bit 5 = 1 selects 8×16 sprite mode. Sprite colour index 0 is transparent (checkerboard); background index 0 is the universal backdrop.

Caveat on the split: in 8×16 mode bit 3 is ignored — the OAM tile byte's own bit 0 picks the table. So sprites can and do draw from the background table: $C59C loads #$9D (bit 0 = 1) to render text as sprites. The two panels are the two pattern tables, not "the sprites" and "the tiles."
