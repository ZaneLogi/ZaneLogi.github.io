Lunar Lander — full 360° rotation, at both ROM sizes

The lander ROM (034599) stores the craft as 9 poses spanning one ~90° quadrant (upright → laid on its side). The full 360° is reconstructed here by X/Y mirroring (dvg.js xFlip/yFlip) — the same reflection trick Atari's Asteroids uses for its ship at $750B. There are two such 9-pose banks at two native sizes: the zoom-out set (dispatch table $4DF4, ~15 units — the far view) and the zoom-in set ($4BA2, ~29 units — the close view as you near the surface).

Note: the exact direction→pose+flip fold lives in the program source (now in hand — MODULE/FRCMLT), but the frame ordering below is still reconstructed geometrically (frames sorted by each rendered shape's actual orientation), not yet re-derived from source. It sweeps smoothly but may not match the original's exact thresholds.

Both drawn at the same pixels-per-unit, so the ~2× native size difference between the two banks is real, not a zoom on this page. Each lander pivots about the DVG origin (0,0) (the red dot ≈ the cabin centre) — a fixed point, so it spins in place instead of wobbling on a per-frame bounding box.

Drawing the lander at different sizes

Two independent mechanisms. (1) The ROM ships the two native sizes above. (2) The DVG globalScale resizes any shape — each step doubles the drawing. Below is the upright zoom-in pose ($4B64) at globalScale 0–5, same pixels-per-unit, so each is twice the previous. Beyond 5 the 4-bit scale field (localScale+globalScale) & 0x0F wraps, so gs≥6 distorts — that's faithful DVG behaviour, not a bug.
