# Ultima VI — 對話系統（Conversation）完整說明

本文整理 `ergonomy-joe/u6-decompiled`（PC/MS-DOS 版 GAME.EXE 逆向重建碼）中 U6 的 NPC 對話系統。它本質上是一個**小型直譯式腳本虛擬機**：NPC 對話編譯成位元組碼存於資料檔，引擎逐位元組解譯，文字直接輸出、控制碼執行效果。配合大量外部遊戲狀態，撐起數百個 NPC 各有性格、可問答、能交易、能訓練屬性、能招募、會記憶、會因玩家為人與劇情進度而變化的龐大對話內容。

主要程式碼：`seg_1703.c`（`talkdr` 對話引擎模組，2013 年逆向）。核心對應早年流傳的逆向文件 `u6converse.txt`。

引擎由五個齒輪構成：

- **`TalkDriver`** — 對話主入口：開場流程 + 玩家輸入迴圈
- **`parse_statement`** — 解譯主迴圈：文字直接印、控制碼分派
- **`C_1703_1D01`** — 關鍵字匹配（KEY/RES）
- **`execute_op`** — 控制指令執行（IF/LET/GIVE/JOIN/HEAL...）
- **`parse_factor`** — 運算式求值：查詢遊戲狀態、運算、修改屬性

---

## 一、腳本格式與緩衝區

- 對話腳本存於 `converse.a`（99 項）和 `converse.b`（125 項）兩個 LZW 壓縮檔，依 NPC 編號對應。
- 啟動時 `LoadConversation` 把該 NPC 腳本解壓到 `TalkBuf`（對話緩衝區），`Talk_PC` 當程式計數器，`PARSE_U8`（= `TalkBuf[Talk_PC++]`）逐位元組讀取。
- 每段腳本三區段，須依序排列：**身分（`OP__FF` 0xFF）→ 外觀（`OP_DESC` 0xF1）→ 對話主體（`OP_MAIN` 0xF2）**。
- 位元組語意：**< 0x80 是可列印 ASCII 文字**（NPC 講的話明文內嵌）；**≥ 0x80 是 opcode**（控制指令或運算子）。
- 資料前綴：`OP_BYTE`（1 byte）、`OP_WORD`（2 byte）、`OP_ADDRESS`（4 byte）。

## 二、對話啟動（`TalkDriver`）

玩家 talk 某對象時進入 `TalkDriver(說話者, 對象)`，先跑一連串「能否交談」閘門，任一不過即拒絕（各有訊息）：

| 條件 | 訊息 |
|---|---|
| 對象是隊友且不在螢幕上（`IsPlrControl` 且離開畫面才檢查，非隊友不走此閘） | "Not on screen." |
| 非單人模式 | "Not in solo mode." |
| 對象是特殊對話 ID（0 或 ≥0xe0）、為死者、且**已開**降靈術（`SeanceFlag`） | "You hear a deep moan." |
| 一般 NPC：死者且**未開**降靈術／睡著／麻痺／逃跑／義警／逮捕／邪惡／混亂陣營 | "No response" |
| 末日後（`IsArmageddon`） | "No response" |
| 對自己說話 | "Talking to yourself?" |
| 腳本載入失敗（無對話資料） | "Funny, no response." |

> **死者與降靈術的閘門關係**（`TalkDriver`，`seg_1703.c:1035-1056`）：死者分兩路處理——對**一般 NPC** 而言「死者且**未開**降靈術」歸入 "No response"（與睡眠/麻痺/敵對同一條件式）；「死者且**已開**降靈術」則放行，可正常對話（見第九節）。"You hear a deep moan." 只發生在**特殊對話 ID**（0 或 ≥0xe0）的死者身上、且降靈術**已開**時。

神龕/狀態物件（`OBJ_18D` 等）用其 quality 值當對話 ID。通過後轉向對象、`LoadConversation` 載入腳本。

### 開場固定流程

1. 從身分段抄出 NPC 名存入 `VarStr['N']`（即 `$N`）。
2. 顯示 NPC 肖像 `C_27A1_02D9`（降靈術或特定物件除外）。
3. 印 "You see " + 外觀描述段；記住外觀段位置 `D_E79D`（供 `look` 重看）。
4. 跳到 `OP_MAIN`，若非直接問答則先跑一段開場白（NPC 主動說的第一句）。
5. 進入問答迴圈 `while(!mustLeave)`（見第六節）。

## 三、解譯主迴圈（`parse_statement`）

```c
opcode = PARSE_U8;
while(不是結束類 opcode) {
    if(opcode < 0x80) {
        CON_putch(opcode);              // (1) 文字直接印
    } else if(opcode == OP_KEY) {
        C_1703_1D01(objNum);            // (2) 關鍵字區塊 → 匹配玩家輸入
    } else {
        execute_op(opcode, objNum);     // (3) 控制指令 → 執行
    }
    if(mustLeave) break;                // OP_LEAVE(bye) 設了結束旗標
    opcode = PARSE_U8;
}
```

遇結束類 opcode（`OP_ASKTOP`/`OP_GET`/`OP_GETSTR`/`OP_ENDRES` 等）停下，等玩家輸入或結束。

## 四、關鍵字匹配（`C_1703_1D01`）— 對話的靈魂

U6 對話是「玩家打字輸入關鍵字 → NPC 給對應回應」。匹配邏輯：

```c
if(玩家輸入為空) 視為 "bye";
while(...) {
    讀出一組逗號分隔的關鍵字;              // 如 "name,who,call"
    if(str_i_compare(腳本關鍵字, 玩家輸入, ...) || 關鍵字[0] == '*') {
        跳到 OP_RES 後的回應內容;
        parse_statement(objNum);          // ★ 遞迴解譯該回應
        return;
    }
    // 沒命中 → 正確跳過該回應(識別 OP_GOTO+4 / OP_BYTE+1 / OP_WORD+2 的變長參數),試下一組
}
```

要點：

- **逗號分隔多關鍵字共用一段回應**；`str_i_compare`（`seg_1703.c:130-145`）做大小寫不敏感的前綴比對：它把**玩家輸入**用空白切成數個詞（`strtok`），任一詞的前綴對得上腳本關鍵字即算命中；關鍵字中的 `?` 是**單字元萬用字元**（該位置任何字元都通過）。
- **`*` 是萬用匹配（catch-all）**，通常放最後當「我不懂你說什麼」兜底。
- **命中後遞迴解譯**回應，回應內可再有文字、IF、嵌套 KEY；`D_E79C` 旗標標記「已在回應中」，避免回應內的 KEY 被當新關鍵字區塊。
- **空輸入預設 "bye"**，所以直接按 Enter 觸發 bye 回應（結束語）。
- 沒命中時須識別變長指令正確略過整段，才能到下一個 `OP_KEY`。

## 五、控制指令（`execute_op`）— 對話能「做事」

關鍵字命中後的回應若含控制 opcode，由 `execute_op` 執行實際效果：

**流程控制**：`OP_IF`/`OP_ELSE`/`OP_ENDIF`（條件分支，呼叫 `parse_factor` 求值）、`OP_GOTO`（跳轉，`Talk_PC = 目標`）、`OP_LEAVE`（結束對話，設 `mustLeave`）。

**變數**：`OP_LET`+`OP_LET_VALUE`（設 `VarInt`/`VarStr`）、`OP_PRINTSTR`（印字串變數或常數字串）。

**物品**：`OP_GIVEOBJ`/`OP_TAKEOBJ`（給/拿物品，4 參數：NPC、物件、品質、數量）、`OP_MOVEOBJ`（放進物品欄）、`OP_TRANSFEROBJ`（從某 NPC 身上找某物轉給另一人）。

**隊伍與行為**：`OP_SETMODE`（設 NPC 的 `NPCMode`，命令去睡/工作）、`OP_GETHORSE`（生成一匹馬給玩家）。（**入隊/離隊** `OP_JOIN` 0xCA、`OP_LEAVEPARTY` 0xCC 不在這個齒輪——它們會回傳狀態值，所以是 `parse_factor` 的運算子，見第七節。）

**角色狀態**：`OP_HEAL`（回滿血）、`OP_CURE`（解毒）、`OP_RESURRECT`（找屍體 `OBJ_153` 復活）。

**道德與旗標**：`OP_ADDKARMA`/`OP_SUBKARMA`（增減業力，0~99）、`OP_SET`/`OP_CLR`（設/清某 NPC 的 `TalkFlags` 位元）。

**世界與呈現**：`OP_REST`（旅館過夜，呼叫 `C_0A33_1355` 快轉到清晨 5 點）、`OP_DELAY`（戲劇性停頓，跑 N×20 幀動畫）、`OP_WAIT`（等按鍵）、`OP_SHOW_CONVERSE`（顯示肖像）、`OP_SHOW_INVENTORY`（開物品欄/交易介面）。

未知 opcode → "Unknown command."

## 六、玩家輸入（`TalkDriver` 問答迴圈）

輸入不只「打關鍵字」，而是一整套 opcode：

| opcode | 行為 |
|---|---|
| `OP_ASKTOP` | 標準提問 "you say:"，讀一行字串當關鍵字 |
| `OP_GETSTR` | 讀字串存入 `VarStr`（記下玩家打的名字等） |
| `OP_GETINT` | 讀整數存入 `VarInt`（數量、價格） |
| `OP_GETDIGIT` | 讀單個數字鍵 |
| `OP_GETCHR` | 讀單個字元 |
| `OP_GET c0..cn` | 限定只接受指定幾個按鍵（如 Y/N） |
| `OP_WAIT` | 等待任意按鍵（分頁停頓） |

支撐議價（輸入數量）、命名/暗號（輸入字串）、選項分支（Y/N）、按鍵繼續等互動。

**兩個內建機制**：

- **`$Z`（`VarStr['Z']`）= 玩家最後一次輸入**，腳本可複述或對未匹配輸入處理。
- **`look` 是引擎硬編關鍵字**：對話中任何時候輸入 "look"，跳回外觀段（`D_E79D`）重播「You see ...」——隨時能再看 NPC 長相，不需每個腳本自己寫。

## 七、運算式求值（`parse_factor`）— 查詢與修改引擎

`parse_factor` 用局部堆疊（`lstack[10]`）求值：讀到資料就 push、讀到運算子就取堆疊頂端運算、結果壓回，直到 `OP_END_OF_FACTOR`（0xA7）**或 `OP_LET_VALUE`（0xA8）**為止（後者讓 `OP_LET` 能用同一個求值器讀出要賦給變數的值）。它遠不只算術，而是對話與遊戲狀態的橋樑：

**狀態查詢（讀狀態做條件）**：`OP_TST`（讀 `TalkFlags` 某位元——劇情記憶判斷）、`OP_WOUNDED`（是否受傷）、`OP_POISONNED`（是否中毒）、`OP_ISINPARTY`（是否在隊伍）、`OP_ISONSCREEN`（是否在畫面）、`OP_HORSED`（是否騎馬）、`OP_WEIGHT`/`OP_CANCARRY`（重量/負重）、`OP_OWNS`/`OP_WHOSGOT`/`OP_TEST_OBJ`（誰有某物）、`OP_OWNER`/`OP_OBJTYPE`（物件擁有者/型別）、`OP_RND`（隨機數）。

**屬性修改（訓練師機制）**：`OP_ADDEXP`（給經驗，上限 9999）、`OP_ADDLVL`（升級）、`OP_ADDSTR`/`OP_ADDINT`/`OP_ADDDEX`（加力/智/敏，各上限 30）。**付錢給訓練師對話即靠這些 opcode 提升屬性/等級。**

**隊伍操作與查詢**：`OP_JOIN`（0xCA，`JoinParty`——NPC 入隊，回傳 0=成功／1=在載具中／2=隊伍已滿）、`OP_LEAVEPARTY`（0xCC，`LeaveParty`——NPC 離隊，回傳同類狀態碼）、`OP__DD`（取隊伍第 N 個成員編號，可限「在畫面上的成員」）。入隊/離隊是**運算子**（會回傳狀態值供 IF 判斷），故在 `parse_factor` 而非 `execute_op`。

**運算與比較**：`OP_ADD/SUB/MUL/DIV`、`OP_AND/OR`、`OP_EQU/SUP/SUPE/INF/INFE/DIF`（= > ≥ < ≤ ≠）——支援複雜條件（如「業力>50 且 已完成任務A」）。

**字串/互動**：`OP_STRSEARCH`/`OP_VALSEARCH`（搜尋）、`OP_SELECT_OBJECT`（彈出 "Select item:" 讓玩家滑鼠點選物件，回傳給對話——交易/鑑定用）。

**取值**：`OP_VARINT`/`OP_VARSTR`（讀變數）、`OP__BC`/`OP__BD`（常數 100）。

## 八、用到的外部資料

對話腳本只是「劇本」，真正讓對話「活」起來的是它讀寫的外部狀態：

**持久狀態（存於 `savegame\objlist`）**：

- **`TalkFlags[]`（最關鍵）** — 每 NPC 一組位元旗標，記錄「某劇情是否發生過」。配合 `parse_factor` 的 `OP_TST`，讓回應因劇情進度而變（第一次 vs 第二次問、任務前後、A 說的話讓 B 多說）。這是對話有記憶、會推進的根本。也被其他系統共用（如 `TalkFlags[5]&0x80` 控制守衛能否逮捕）。
- **`KARMA`** — 全域業力（0~99），對話可增減；又反過來影響 NPC 態度與善惡判定。
- 各角色的 `Party`/`HitPoints`/`NPCMode`/`STREN`/`INTEL`/`DEXTE`/`ExpPoints`/`Level`/物品欄等。

**執行期變數**：`VarInt[]`/`VarStr[]`（暫存值 + 動態文字 `$N` NPC 名、`$P` 玩家名、`$Y` 對話中提到的人、`$Z` 最後輸入）。其初值來自對話開始前灌入的玩家屬性/時間/業力（`seg_16E1.c:14-37`）——所以對話讀得到玩家是誰、做過什麼。

> **完整內建變數表**（`seg_16E1.c:14-37`，移植 I-13 時可直接照搬）。注意 `$` 字串與 `#` 整數是**兩個不同陣列**，同一字母可分屬兩者（如 `$Y`=提到的人、`#Y`=年）：
>
> | 字串 `$` | 意義 | 整數 `#` | 意義 |
> |---|---|---|---|
> | `$G` | 敬稱（`milady`/`milord`，依性別） | `#A` | PC 敏捷 |
> | `$N` | NPC 名（開場時填入） | `#D` | 日 |
> | `$P` | PC 名（`Names[partyId]`） | `#E` | PC 經驗值 |
> | `$T` | 時段（`morning`/`afternoon`/`evening`，依 `Time_H`） | `#G` | 性別旗標 |
> | `$Y` | 對話中提到的人（`OP__D8`/`OP__DF` 設定） | `#H` | 時 |
> | `$Z` | 玩家最後輸入 | `#I` | PC 智力 |
> | | | `#K` | 業力 `KARMA` |
> | | | `#L` | 語言 |
> | | | `#M` | 月 |
> | | | `#O` | 隊伍人數−1 |
> | | | `#P` | PC 生命值 |
> | | | `#S` | PC 力量 |
> | | | `#W` | NPC 的 `NPCMode`（工作型態） |
> | | | `#Y` | 年 |
>
> （變數以字母索引：`VarStr[字母 - 0x37]`、`VarInt[字母 - 0x37]`。此外 `$0~$9`/`#0~#9` 是通用暫存暫存器，每次對話開始時清空——`VarInt[0..9]=0`、`VarStr[0..9]` 重設為空字串緩衝；整套設定都在 `TALK_initTalk` 內，灌完變數才呼叫 `TalkDriver`。）

**呈現資源**：NPC 肖像圖（`C_27A1_02D9` 載入的獨立圖檔）。

**世界系統接口**：時間（`C_0A33_1355`，過夜）、物件系統（`GiveObj`/`TakeObj`）、隊伍、戰鬥狀態——對話透過 opcode 呼叫。

> 對話資料刻意分散：劇本在 `converse.a/.b`、記憶在 `objlist` 的 `TalkFlags`、肖像在圖檔、動態值在 `VarInt/VarStr`——引擎在對話進行時把它們組裝起來。

## 九、特殊機制

- **降靈術（`SeanceFlag`）**：劇情中開啟後可與死者對話（啟動閘門放行死者），且跳過肖像顯示（對象是亡靈）。
- **`look` 重看外觀**：見第六節，引擎硬編。
- **`$Z` 複述輸入**：見第六節。
- **遞迴解譯**：回應、IF 分支、關鍵字回應都透過遞迴 `parse_statement` 處理，可任意嵌套。

## 十、完整對話流程

```
玩家 talk NPC
   │
   ▼
TalkDriver ── 閘門檢查(在螢幕/非單人/非敵對/非睡眠/非末日...)
   │  通過 → LoadConversation 解壓腳本到 TalkBuf,失敗→"Funny, no response."
   ▼
開場 ── 取 $N、顯示肖像、印 "You see"+外觀(記住位置供 look)、跑開場白
   │
   ▼
問答迴圈 while(!mustLeave):
   ├─ 等輸入(ASKTOP/GETSTR/GETINT/GETDIGIT/GETCHR/GET[Y/N]/WAIT) → 存 $Z
   ├─ 輸入 "look" → 跳回外觀段重播
   └─ 否則 parse_statement 解譯:
        ├─ <0x80 文字 → 直接印
        ├─ OP_KEY → C_1703_1D01 關鍵字匹配(逗號分隔/`*`兜底)
        │      命中 → 遞迴解譯回應(可含 execute_op + parse_factor)
        ├─ execute_op → IF/LET/GIVE/JOIN/HEAL/KARMA/SET-flag/REST...
        └─ parse_factor → 查詢狀態 / 運算 / 改屬性(訓練師)
   │
   ▼ (輸入 "bye" 或 OP_LEAVE → mustLeave)
結束對話,還原狀態列
```

## 十一、設計總結

U6 的對話系統是一個精巧的小型腳本虛擬機：

- **腳本即位元組碼**：文字明文內嵌（<0x80）、控制邏輯用 opcode（≥0x80），`Talk_PC`+`TalkBuf` 逐位元組直譯。引擎與內容徹底分離，內容可無限擴充而不動引擎。
- **關鍵字驅動的分支對話**：逗號分隔關鍵字 + `*` 兜底 + 命中遞迴，造就「輸入 name/job 問背景、輸入劇情詞推進任務」的經典體驗；輸入模式多達七八種，支撐議價、命名、Y/N、暗號。
- **能改變並記住世界**：透過 `execute_op` 指令集（交易、招募、治療、復活、訓練、給馬、過夜）與 `parse_factor` 查詢/修改（讀旗標屬性、改經驗等級屬性），對話不只讀文字，而是能交易、招募、訓練、推進劇情、依玩家為人與進度變化的互動系統。
- **記憶的根本是 `TalkFlags`**：腳本（劇本）+ 外部狀態（尤其 `TalkFlags` 記憶、`KARMA`/變數讀玩家），合起來才構成「會記憶、會因進度與你的為人而變」的對話。
