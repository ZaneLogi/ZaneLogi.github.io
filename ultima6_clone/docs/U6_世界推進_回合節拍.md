# Ultima VI — 世界推進 / 回合節拍（核心）

本文整理 `ergonomy-joe/u6-decompiled`（PC/MS-DOS 版 GAME.EXE 逆向重建碼）中 U6 最根本的運作框架：**整個世界由玩家行動驅動**。世界時鐘、行動點數、NPC 排程、生怪、火把燃燒、動畫、狀態效果——全部掛在「玩家採取一個行動 → 世界推進一拍」這個節拍器上。這是其他所有子系統的共同心跳。

主要程式碼：`seg_0A33.c`（主迴圈、世界推進 `C_0A33_1355`、動畫）、`seg_1E0F.c`（移動、行動點、NPC 推進 `C_1E0F_5165`）。

---

## 一、世界由行動驅動：阻塞式主迴圈

主控制迴圈 `C_0A33_1CB4` 的骨架：

```c
do {
    RefreshStatus();
    ch = CON_getch();        // ★ 阻塞:無限期停在此處等待玩家按鍵
    switch(ch) {             // 玩家做了什麼(走/攻擊/用物品/施法/pass...)
        ...執行該動作,以 SubMov 扣行動點...
    }
    // 動作完成 → 觸發世界推進(時間/NPC/燈火/動畫/狀態...)
} while(...);
```

**關鍵在 `CON_getch()` 是阻塞式輸入**：程式執行到此完全停下，在玩家按鍵前什麼都不發生——NPC 不動、時間不走、火把不燒、海水凝固。

因此 U6 不是純即時（發呆不會被敵人偷襲），而是**行動驅動的半即時**：

- 不像純回合制有明確的「我方/敵方回合」分界——平時走路時回合循環飛快、無縫，感覺像連續移動。
- 不像純即時世界會自走——沒有輸入，世界完全暫停。
- 只有**戰鬥**時多方輪流、循環變慢，底層回合節拍才浮上檯面，讓人明確感到「等大家輪完才到我」。

> 技術上，程式可以「安心停在 `CON_getch()` 等待」，不必持續跑即時模擬迴圈——省 CPU、邏輯簡單，且天然讓所有子系統同步在「每行動推進一次」這個統一節拍上。玩法上，給玩家從容思考的空間，同時保留「行動有時間代價」的沉浸感。

## 二、行動點數（Move Points）：行動配額與速度系統

### 2.1 配額 = 敏捷

`MovePts[]`（每角色一個，存於 `savegame\objlist`）是該角色當前剩餘行動力。每回合補充時：

```c
MovePts[i] = (MovePts[i] < 0) ? (MovePts[i] + DEXTE[i]) : DEXTE[i];
```

**每回合行動點 = 敏捷值 `DEXTE`**。敏捷高者每回合能做更多事——這是 U6 把「敏捷」屬性轉化為實際效果（行動次數/速度）的主要途徑。

### 2.2 消耗 = 動作成本 × 速度修正（`SubMov`）

```c
SubMov(int objNum, int cost) {
    if(GetType(objNum) == OBJ_1AF)           cost >>= 1;  // 騎馬:消耗減半
    if(SpellFx[10] && IsPlrControl(objNum))  cost >>= 1;  // 加速魔法:減半
    else if(SpellFx[7] && Is_ATKPLR(objNum)) cost <<= 1;  // 減速魔法(敵):加倍
    if(cost < 1) cost = 1;                                // 至少扣 1
    MovePts[objNum] -= cost;
}
```

速度系統全靠調整「每動作扣多少點」實現：騎乘、加速/減速增益減益，都是改消耗。基礎成本多為 5（走一格、用物品、跟隨移動）。

### 2.3 透支借貸（跨回合慢動作）

補充公式裡 `MovePts < 0` 的分支是精妙處：某些動作消耗可超過當前剩餘點數，使 `MovePts` 變負（透支）。U6 允許完成該動作，但**下回合補充時先扣掉欠的**（`MovePts + DEXTE`）。於是「消耗大於一回合配額的慢動作」能自然橫跨多回合——一次重攻擊可能讓接下來一兩回合行動受限。用簡單的負數累加，就模擬出動作有不同速度/恢復時間的連續感。

### 2.4 平時移動：地形與載具決定消耗（`C_1E0F_1B0E` 結尾）

玩家走一步成功後，依型態扣點：

| 型態 | 消耗 |
|---|---|
| 步行 | `SubTerrainMov`（**隨腳下地形**：道路便宜、沼澤/森林/山地昂貴） |
| 對角線 | 額外 `SubMov(5)`（近似 √2 距離） |
| 騎馬/木筏 | `SubMov(5)`（騎馬再經 `SubMov` 內部減半） |
| 帆船/獨木舟 | `D_180A[(dir - WindDir) & 7]`（**依航向與風向夾角**：順風便宜、逆風昂貴、無風不動） |

所以平時移動中，行動點是「速度與時間的調節器」：難行地形、逆風、對角都讓你走得「慢」（耗點多→世界時間流逝快），騎馬則又快又省。

### 2.5 全隊步調同步

世界推進迴圈中（`seg_1E0F.c`）：

```c
for(i = 1; i < PartySize; i++)
    if(NPCMode[Party[i]] == AI_FOLLOW && MovePts[Party[i]] <= 0)
        MovePts[Party[0]] = 0;   // 任一跟隨隊員耗盡 → 強制領隊(玩家)也歸零
```

只要有跟隨隊員行動點用完，就把領隊點數清零、強制推進回合讓全隊一起補充。**全隊移動被最慢/最累的成員拖著走**，步調一致——這是為何隊伍總是整體移動，不會散成長龍。

### 2.6 主動放棄回合

各處的 `MovePts[...] = 0` 是「放棄本回合剩餘行動」：玩家按 pass（`MovePts[Active] = 0`）、受阻 NPC 原地等待（前述移動受阻降級）、撞牆不扣點（不算行動）等。

## 三、世界推進：一次「心跳」（`C_0A33_1355`）

玩家行動耗盡點數後，呼叫 `C_0A33_1355(minutes)` 推進世界，`minutes` 即本次行動花費的遊戲分鐘數（隨動作而異）。一次推進處理大量事項：

### 3.1 時間停止法術（最優先）

```c
if(SpellFx[14]) {                       // 時間停止生效中
    if(SpellFx[14] <= minutes) { SpellFx[14] = 0; ... }
    else { SpellFx[14] -= minutes; return; }   // ★ 直接 return,世界其他部分完全不推進
}
```

施法期間 `C_0A33_1355` 直接返回，只有玩家能動，連海水都凝固（動畫更新也檢查 `SpellFx[14]`）。這是「世界由行動驅動」的極致——連時間流逝都是可被魔法暫停的一個變數。

### 3.2 限時效果遞減

```c
for(i = 0; i < 16; i++)
    if(SpellFx[i]) { SpellFx[i] = (SpellFx[i] <= minutes) ? 0 : SpellFx[i] - minutes; }
```

所有 16 種限時魔法效果（加速、減速、隱形、保護、時間停止……）按經過分鐘遞減，到期解除。火藥桶倒數（`D_2CA4`）、火山爆發判定也在此。

### 3.3 玩家裝備與消耗品（按分鐘）

遍歷玩家隊伍，處理隨時間運作的物品：

- **火把/燈籠**（`OBJ_05A` frame 1）：`SubQuan(di, minutes)` 按經過分鐘燃燒，燒完 "BurnOutMsg" 熄滅。**站著不動則永不變短**（不行動→不推進）。
- **再生戒指**（`OBJ_101`）：`HitPoints += minutes` 隨時間回血；小機率損壞消失。
- **暴風斗篷**（`OBJ_051`）、其他戒指：各有按分鐘的效果與小機率損壞（"RingVanishedMsg"）。

### 3.4 狀態效果的逐分鐘擲骰

對每個角色、每經過的一分鐘擲骰，決定狀態是否解除或造成傷害：

```c
for(bp_14 = 0; bp_14 < minutes; bp_14++) {
    if(IsInvisible(i) && rand(0,63)==0 && GetInt(i) <= rand(1,30)) ClrInvisible(i);
    if(IsProtected(i) && ...) ClrProtected(i);
    if(IsCursed(i)    && rand(0,15)==0 && GetInt(i) >= rand(1,30)) ClrCursed(i);
    if(IsCharmed(i)   && rand(0,7)==0  && ...) COMBAT_stopCharm(i);
    if(IsParalyzed(i) && rand(0,3)==0  && GetStr(i) >= rand(1,30)) ClrParalyzed(i);
    if(IsAsleep(i)    && rand(0,15)==0) { ClrAsleep(i); ... }
    if(IsPoisoned(i)  && !IsProtected(i) && rand(0,7)==0) LooseHP(i, 1);  // 中毒掉血
}
```

智力高者較快擺脫隱形/詛咒/魅惑、力量高者較快掙脫麻痺、中毒每分鐘有機率掉血。所以「經過越多遊戲時間，狀態越可能改變」——而時間又由行動驅動。

### 3.5 時鐘累進：分 → 時 → 日 → 月 → 年

```c
for(bp_12 = Time_M + minutes; bp_12 > 59; ) {
    bp_12 -= 60;
    if(++Time_H > 23) {              // +1 小時
        Time_H = 0;
        if(++Date_D > 28) {          // +1 天 (U6 一個月 28 天)
            Date_D = 1;
            if(++Date_M > 12) {      // +1 月 (一年 12 月)
                Date_M = 1;
                Date_Y ++;           // +1 年
            }
        }
    }
    if(NextSleep) NextSleep--;       // 睡眠冷卻
    if(DrunkCounter) DrunkCounter--; // 醉酒消退
    C_1E0F_5165();                   // ★ 每「跨小時」觸發 NPC 排程時鐘(切換作息)
    // 隊伍中特定職業每小時回魔(MAGIC += Level)
}
```

要點：

- U6 曆法：**60 分/時、24 時/日、28 日/月、12 月/年**。
- `Time_M` 累加 `minutes`，每滿 60 進位一小時，連鎖進位到日/月/年。
- **每跨一小時呼叫 `C_1E0F_5165`**——這正是 NPC 排程時鐘（見《NPC 排程與移動》§二），比對 NPC 排程條目時間、切換作息目標。所以 NPC 的「生活作息」推進，是掛在世界時鐘的每小時跳動上，而時鐘又由玩家行動驅動。
- 睡眠冷卻、醉酒消退按小時遞減；牧師類隊員每小時回魔。

### 3.6 每小時的環境更新

```c
if(D_0369 != Time_H) {              // 進入新的一小時
    MustRingBell = 1;               // 教堂該報時鳴鐘(對應 NPC 的 AI_RINGBELL)
    MUS_Clock = Time_H % 12;
    // 日晷(sundial)tile 依時段更新外觀
    if(Time_H > 20 || Time_H < 5) bp_10 = TIL_13C;       // 夜
    else bp_10 = TIL_148 + ((Time_H - 5) >> 1);          // 日,隨時段變
    GR_4B(BaseTile[OBJ_0EB], bp_10);
    D_0369 = Time_H;
}
```

整點觸發報時鳴鐘、更新日晷外觀（隨時段變化的太陽位置）、設定時鐘音樂等。晝夜也據 `Time_H` 判定（影響光照、日蛋/夜蛋孵化等）。

## 四、一次行動觸發的完整連鎖

```
玩家按鍵 (CON_getch 解除阻塞)
   │
   ▼
執行動作 (走/攻擊/用物品/施法...) → SubMov 扣行動點
   │  消耗依:地形 / 對角 / 載具 / 風向 / 騎乘減半 / 加速減速魔法
   ▼
(行動點耗盡 → 推進回合) C_0A33_1355(minutes)
   ├─ SpellFx[14] 時間停止? → 是則 return,世界凍結
   ├─ 16 種限時魔法效果遞減、火藥桶倒數
   ├─ 火把按分鐘燃燒、再生戒指回血、裝備損壞判定
   ├─ 每分鐘擲骰:隱形/詛咒/麻痺/中毒... 狀態變化
   ├─ 時鐘累進 分→時→日→月→年
   │     每跨小時 → C_1E0F_5165 (NPC 排程切換作息)
   │              → 牧師回魔、睡眠/醉酒冷卻
   └─ 每小時 → 報時鳴鐘、日晷外觀、晝夜
   │
   ▼
全體補充行動點 MovePts = DEXTE (透支者還債)
   │
   ▼
NPC AI 推進 (排程/移動/受阻處理)、EGG 生怪掃描、動畫前進
   │
   ▼
回到主迴圈,再次 CON_getch 等待下一個行動
```

> 生怪（`EGG_hatchArea`）見《生怪系統 蛋EGG》；NPC 移動與排程見《NPC 排程與移動》；tile/物件動畫見《動畫機制》——三者都是這個心跳上的齒輪。

## 五、設計總結

U6 的核心是一個**圍繞玩家行動轉動的世界**——你動，它才動：

- **阻塞式主迴圈**：世界停在 `CON_getch` 等待，玩家行動才推進一拍。半即時：平時無縫流暢，戰鬥才顯回合。
- **行動點＝敏捷配額**：一個整數承載回合節奏、敏捷的意義、騎乘/增益/減益的速度差異、慢動作的跨回合透支借貸。平時當「速度與時間調節器」，戰鬥時才浮現為明確配額。
- **世界時鐘＝行動次數的累積**：遊戲時間不按真實流逝，而按玩家行動量累進；昂貴行動（難行地形、逆風）推進更多時間。每跨小時驅動 NPC 作息，每小時驅動報時、晝夜。
- **一次心跳，萬事連動**：法術計時、火把、狀態擲骰、回血、NPC 排程、生怪、動畫——全擠在 `C_0A33_1355` 這一次推進裡同步發生。

這套「行動驅動的統一節拍器」讓 U6 用極省的方式（一個阻塞迴圈 + 一個整數配額 + 一個由行動累進的時鐘），既撐起從容可思考的 RPG 漫遊，又撐起緊湊的回合戰鬥，並讓一個會作息、會生怪、會流動的「活世界」隨玩家步調運轉。
